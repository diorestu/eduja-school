# Audit selama pengerjaan: Tutup Buku BOS

Tanggal: 15 November 2026, Asia/Makassar.
Mode: selama pengerjaan, sesuai permintaan pengguna. Referensi: screenshot Tutup Buku BOS yang dilampirkan dalam chat.

## Arah dan keputusan

Task UI Bendahara dengan komponen EDUJA, teal sebagai aksen aksi utama, font aplikasi dan tema yang sudah tersedia. ENERGY 1 / RHYTHM 2 / MOTION 1. Lima kolom menunjukkan urutan pada layar lebar; layar sempit menumpuk langkah secara berurutan. Ringkasan realisasi, saldo fisik dan riwayat dipisahkan karena kegunaannya berbeda.

Angka, sekolah, pengguna, persetujuan dan nomor referensi pada screenshot tidak disalin. Grafik realisasi memakai batang per komponen agar label panjang terbaca dan dapat dibandingkan di mobile; saat belum ada pengeluaran, tampil keadaan kosong, bukan grafik contoh.

## Temuan yang ditangani selama pengerjaan

1. R-17/R-38: contoh pemasukan/pengeluaran tidak menjadi data aplikasi. Sisa dana dibolehkan; keseimbangan memeriksa saldo awal + mutasi = saldo fisik, bukan keharusan menghabiskan anggaran.
2. R-27: tahun/sumber yang belum diperiksa, data kosong, dokumen hilang, tahun BOS ambigu, transaksi pending, posting tertinggal, data berubah, riwayat lama dan penutupan yang dibuka kembali memiliki keadaan eksplisit. Laporan saldo kosong memiliki pesan, bukan tabel tanpa isi.
3. R-26: checkbox wajib mengaktifkan konfirmasi; perubahan tahun/sumber menonaktifkannya dan memerlukan pemeriksaan ulang. Catatan opsional dibatasi 200 karakter. Catatan kosong dari validasi lama dinormalisasi agar penghitung tidak memicu error JavaScript.
4. R-03/R-32: layar 320 dan 390 px diperiksa, tidak ada elemen area kerja melewati viewport; fokus keyboard memiliki outline solid pada Cek Kesiapan.
5. R-36/R-38: tidak menampilkan persetujuan kepala sekolah yang tidak pernah dicatat. Bukti memuat pelaku aktual, waktu, catatan, nomor referensi dan sidik data dari snapshot.
6. Kebenaran saldo: saldo rekening bersama diberi label fisik; dompet adalah alokasi dan tidak dijumlahkan kembali. Pagu tahun anggaran sekolah yang beririsan dijelaskan terpisah dari realisasi tahun BOS pada transaksi.
7. Perlindungan data: tahun mengikuti bos_year, bukan tanggal kalender semata. Dokumen harus tersedia pada storage. Transfer rekening bersama dikunci secara konservatif pada tahun tertutup; mutasi dompet mengikuti sumber transaksinya. Snapshot per sumber tidak digunakan sebagai saldo awal generik ledger yang masih dapat berubah untuk sumber lain.

Tidak ada temuan penting yang belum diselesaikan dari review kode terpisah.

## Bukti verifikasi

- Browser plugin tidak tersedia; Playwright CLI menguji server lokal pada desktop 1920 x 1080, mobile 390 x 844 dan 320 x 740.
- Kondisi awal/kosong dan siap dikonfirmasi dirender. Tahun dan sumber dapat diubah; tombol konfirmasi sebelumnya aktif kembali disabled setelah pilihan berubah. Catatan dan penghitung diperiksa.
- Laporan keuangan terbuka; tombol cetak memanggil window.print. Dialog cetak OS dan hasil PDF fisik tidak diperiksa.
- Tema terang dan gelap diperiksa setelah transisi dan preloader selesai. Console alur aplikasi: 0 error, 0 warning.
- Delapan tes BOS mencakup sumber/tahun/sekolah, saldo tersisa, stale review, snapshot, dokumen hilang, pemetaan ambigu, pajak, revisi yang masuk ke tahun terpilih, penguncian transfer/dompet, saldo historis negatif, konfirmasi HTTP dan laporan/bukti lintas sekolah.
- Full suite: 334 tes / 2.183 assertion lulus. Setelah perbaikan pesan kosong laporan, 56 tes finance / 655 assertion lulus. Build Vite lulus; peringatan bundle besar aplikasi tetap ada. git diff --check bersih.
- Penutupan berhasil dan keadaan terblokir diuji dengan database pengujian. Tidak ada tahun BOS pada data pengguna yang ditutup untuk pengujian browser.

## Delivery gate, terbatas pada bukti di atas

PRODUCT PASS: alur lima tahap, laporan, saldo awal dan riwayat nyata; evidence Thin, satu referensi pengguna.
UX PASS: urutan jelas; persetujuan eksplisit; data berubah memerlukan pemeriksaan ulang.
UI PASS: task UI mengikuti arah EDUJA dan hierarki screenshot.
DESIGN SYSTEM PASS: work-field, work-btn, token, font dan tema aplikasi dipakai kembali.
ACCESSIBILITY PASS (terbatas): label, status teks, field native, Tab dan outline diperiksa; bukan audit WCAG menyeluruh.
RESPONSIVE PASS: 1920, 390 dan 320 px; tidak ada elemen area kerja keluar viewport pada 320 px.
EDGE CASES PASS: state dan regression tests yang disebutkan di atas.
CODE QUALITY PASS: test, build, syntax check dan review kode terpisah.
VISUAL QA PASS (terbatas): screenshot terang/gelap/mobile/report; hasil penutupan aktual diuji HTTP, bukan pada data pengguna.
ANTI-SLOP PASS: tidak ada angka/aset/persetujuan palsu, kontrol tanpa aksi atau dekorasi yang tidak membantu pekerjaan pada perubahan ini.
FINAL PASS sesuai lingkup yang diperiksa; belum diuji dengan pengguna akhir.
